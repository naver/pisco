**Relevance to PISCO: low.** Robotics paper (vision-language-action policy). The one shared idea is
"a few learned tokens summarise an observation and are cached for later steps". It never compares that
summary against the uncompressed past, so it says nothing about compression fidelity, which is PISCO's
question. No arm proposed.

## Claim in one paragraph
The paper reports a 2.4B vision-language-action model (Qwen3.5-2B VLM + 0.2B flow-matching action
expert) pretrained only on public robot / egocentric / vision-language data that sets a new
size-vs-success Pareto frontier on three robot benchmarks (LIBERO-Plus, RoboTwin Clean2Rand,
RoboCasa365, p.1-2). Its second claim: giving the action expert a memory of the last K-1=2 frames
through 32 cached "register" tokens per frame raises success by 1.5 to 5.5 points in simulation and
12 to 17.5 points on real-robot tasks, makes pose oscillations about 4x rarer, and adds under 1% latency
(p.1, p.9, p.12, p.22).

## Method — what is actually new
- **Registers as memory (§4.1, p.4).** 32 learnable tokens per frame sit in the action expert's stream.
  They cross-attend the VLM's final-layer hidden states of that frame, self-attend the registers of
  earlier frames, never read the action tokens. Their keys/values are kept in the expert's KV cache as a
  rolling window of K-1 frames. Why it helps: the policy sees its recent past, which breaks "perceptual
  aliasing" (two look-alike states that map to each other, p.9).
- **Every frame in the window is supervised (Eq. 6, p.5).** A training window of K=3 frames (1 s stride)
  is one batched pass; each frame has its own action loss conditioned on the registers up to it. So the
  registers get gradient from all later frames, and no recurrence has to be unrolled.
- **Zero extra encoder cost (§4.2, p.6).** The VLM encodes each frame once, as in a memoryless policy;
  only (K-1)·32 KV pairs per expert block are carried over. 22.1 ms/chunk without registers,
  22.8 ms at K=3, 24.6 ms at K=32 on one H100; cache ≈ 2 MiB per past frame (p.22, n = median of 2×200 chunks).
- Everything else (flow-matching expert, cross-attention conditioning, 8 noise draws per encoder pass,
  public-data curation) is adopted from Qwen-RobotManip / π0 / Qwen-VLA and is not claimed as new (p.3-5).

## Ablations that matter for us
- Memory window at train vs eval (Fig. 5a, p.9): a model trained with K=3 but evaluated with K=1 scores
  like a model trained at K=1 (88.9 / 67.2 / 34.9). The paper infers the gain comes from *reading* the
  past at inference, not from window training. Not transferable to PISCO (we never drop the memory at eval).
- **Missing: no "uncompressed past" baseline.** The paper never feeds the raw past frames to the VLM
  (its Fig. 2a alternative), so there is no measure of what the 32 registers lose versus the full
  observation. That is exactly the fidelity question PISCO lives on, and this paper does not answer it.
- Missing: register count (32 is fixed), register placement, and any text-only or retrieval setting.

## Mapping to this project
What REKI's registers are, in PISCO terms: decoder-side learned query tokens that read the encoder's
hidden states by cross-attention and are then cached as KV. PISCO does the mirror image: the summary is
read off the *compressor's* `<MEM>` positions and injected into the decoder as input embeddings through
the connector. Both compress one observation into a few tokens once and reuse them; PISCO already
computes compressed embeddings once per chunk, and `AgentTrajCollator` already compresses past steps of
a trajectory (`pisco/collator.py:570`). So the paper's mechanism adds nothing we lack.

The only idea with a conceivable PISCO use is "supervise every step of a window with the compressed past
as context" for agentic trajectories. That is a collator-level change whose value would have to be
established on our agent-QA eval, and nothing in this paper (robot success rates, no fidelity baseline)
raises its prior. Champion to beat if it were ever tried: the v4+KL multimodal finetune
(docs/multimodal_results.md) for mm, or the 4B→4B finetune 149908 (LongBench f1 34.7) for text.

## Risks / open questions
- Different problem: temporal memory for control (disambiguating look-alike states), not information
  retention from a document. REKI's register budget (32 tokens per 2 cameras ≈ up to ~800 visual tokens)
  is a ~25x squeeze that is never scored for recall of content.
- Open for us, not answered here: would decoder-side query tokens (cross-attention readout, Perceiver /
  xRAG style) beat compressor-side `<MEM>` extraction at equal token budget? This paper gives no evidence
  either way; it would be a separate design study, not a replication.
